## 1. API on Render

1. In Render: **New → Blueprint**, then pick the `hoardrun-backend-py` repository. Render reads `render.yaml` and asks for every `sync: false` value.
2. Fill those in. The table below says where each comes from. Leave a provider blank until it's set up; that feature then says it isn't set up yet.
3. Deploy. Each deploy runs `python -m app.database.migrate upgrade` (as `MIGRATION_DATABASE_URL`) **before** the new version takes traffic. If it fails, the old version stays live.
4. Add a custom domain (for example `api.hoardrun.com`). Render issues the TLS certificate.

What the blueprint sets up:
- **Plan `standard`, always on.** Stripe gives Hoardrun under 2 seconds to approve a card payment. A free instance that sleeps would decline every first payment, and webhooks would time out.
- **Two worker processes** (`WEB_CONCURRENCY=2`), each with a 5 + 5 connection pool. That's 20 database connections at most.
- **Real client IPs from Render's load balancer** (`--proxy-headers`). Rate limits and signed agreements depend on them. Without it, every user would share one rate limit.
- **Health check on `/health`, non-root user, no `Server` header.**

| Variable | Value |
|---|---|
| `DATABASE_URL` / `MIGRATION_DATABASE_URL` | App user / owner connection strings (production-database.md) |
| `DATA_ENCRYPTION_KEY` | `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`. Keep a copy in your password manager. |
| `APP_URL` | The web app's address, for example `https://hoardrun.com` (used in email links) |
| `CORS_ORIGINS` | `["https://hoardrun.com"]`: only the web app's own address(es) |
| `JWT_SECRET_KEY`, `SECRET_KEY` | Generated by Render. Changing them signs everyone out. |
| Stripe, Plaid, Resend, Google, Persona, Alpaca, Anthropic | From each provider's dashboard |

## 2. Webhooks to register

Use the API's public address in each provider's dashboard:

| Provider | URL | Events |
|---|---|---|
| Stripe (payments) | `/api/v1/payments/stripe/webhook` | `checkout.session.completed`, `checkout.session.async_payment_succeeded` |
| Stripe (Issuing) | `/api/v1/issuing/webhook` | `issuing_authorization.request`, `issuing_authorization.updated`, `issuing_transaction.created` |
| Plaid | `/api/v1/plaid/webhook` | Transfer and item webhooks (also set as `PLAID_WEBHOOK_URL`) |
| Persona | `/api/v1/identity/webhook` | Inquiry events |

Google sign-in's redirect URI is on the **web app**: `https://<web app>/auth/google/callback`.

## 3. Web app on Vercel

1. Import the `hoardrun` repository in Vercel. It's detected as Next.js.
2. **Settings → Environment Variables**: `NEXT_PUBLIC_API_URL = https://<api address>/api/v1`. This is baked in at build time, so redeploy after changing it.
3. Add the custom domain. Vercel issues the certificate.
4. **Settings → Functions**: keep the region at `iad1` (also set in `vercel.json`).

Security headers on every page (`next.config.mjs`):
- **A Content Security Policy** that only allows the API, Stripe, Plaid and Binance. Adding a new outside script, frame or API means adding it there, or the browser blocks it.
- **HSTS, no framing, no camera/microphone/location, and a strict referrer policy.**

## 4. After the first deploy

- [ ] `https://<api>/health` returns `healthy`.
- [ ] `https://<api>/api/health/database` returns `healthy` and shows no password.
- [ ] Sign up, confirm the email code, sign in, and add money on the live site.
- [ ] Each provider's dashboard shows its webhook delivering.
- [ ] Response headers on the web app include `Content-Security-Policy` and `Strict-Transport-Security`.
- [ ] Set up uptime alerts on `/health` (Render notifications, or a service like Better Stack) and error alerts from the logs.

## 5. Running it elsewhere

The `Dockerfile` runs anywhere that runs containers (Fly.io, Railway, AWS App Runner, Cloud Run). Set the same variables, and run `python -m app.database.migrate upgrade` before each release. Hosts that read a `Procfile` get the same two steps from it.
